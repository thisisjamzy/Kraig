# Dreda Ledger — spreadsheet schema

Primary database, replacing Notion for now (see the architecture doc for why: no rate
limits, no relation-chain workarounds, Apps Script talks to it directly). `Dreda-Ledger.xlsx`
already has all of this built, with formulas, dropdowns, and a starter seed of your real
account and category names. Import it into Google Sheets and it's ready.

Every tab's header row is row 1. Columns shaded green in the workbook are live formulas,
pre-filled thousands of rows down, never write into them directly, Apps Script writes
around them (see "How inserts work" below).

## BudgetRules

The redesign at the center of the pivot. One row per budget, recurring or not, no
per-month duplication. Apps Script reads these fields and computes what a rule means for
any month on request, nothing here gets materialized into a new row when a period turns
over.

| Column | Type | Notes |
|---|---|---|
| ID | text | `rule_xxxxxxxx` |
| CategoryID | text | → Categories.ID |
| Description | text | |
| BudgetedAmount | number | per occurrence |
| Frequency | dropdown | Once, Weekly, Monthly, Quarterly, Yearly |
| Interval | number | e.g. 2 with Monthly = every 2 months |
| AnchorDate | date | first occurrence, and which day/weekday it repeats on |
| EndCondition | dropdown | Never, After Occurrences, On Date |
| EndOccurrences | number | used when EndCondition = After Occurrences, maps to the app's `recurrenceMonths` |
| EndDate | date | used when EndCondition = On Date |
| AccountID | text | optional, restricts the rule to one account |
| Tag | text | optional, free label (e.g. a location) |
| Archived | boolean | soft-delete, keeps history |

Seeded with two real rules from the app's placeholder budget (Subscriptions, Entertainment),
both Monthly, both open-ended.

## BudgetProgress

Not written to directly. Regenerate it from the sheet's **Dreda → Refresh Budget Progress**
menu, it snapshots the current month's rules against actual spend, for glancing at inside
Sheets the way the old Notion "Active Budget" gallery view worked. The app itself calls
`budgets.listRules` / `budgets.summary` and never touches this tab.

## Settings

Key/value. `TotalBudget` (the monthly ceiling shown on the Budget screen's gauge),
`DefaultCurrency`, `DisplayCurrency`, `Timezone`, `HouseholdName`. Edit the Value column
directly, or flip `DisplayCurrency` through the `settings.setDisplayCurrency` action instead
of by hand, see **Multi-currency** below.

| RateToBase | number | how many units of `Settings!DefaultCurrency` equal 1 unit of this currency |
| UpdatedAt | date | |
| Notes | text | source, or "fixed peg" for currencies that don't float |

Seeded with XAF (the base, rate 1), EUR (655.957, the fixed CFA franc peg, this one never
needs updating), and market rates for USD and GBP as of Aug 29, 2026 (source: xe.com,
update these two periodically, market rates drift). Add a row here for any other currency
before switching `DisplayCurrency` to it, `settings.setDisplayCurrency` refuses the switch
otherwise rather than silently showing wrong numbers.

## Multi-currency

Every account keeps its own recorded currency (its `Currency` column), and every amount
ever written, a Transaction, a Transfer, a BudgetRule's `BudgetedAmount`, stays in the
currency of the account it belongs to, permanently. Nothing on this sheet is ever
rewritten into a different currency.

`Settings!DisplayCurrency` is the toggle: switch it (via `settings.setDisplayCurrency`,
payload `{ "currency": "USD" }`) and every *read* action, accounts, transactions,
transfers, budgets, the two dashboards, converts its numbers into that currency on the
way out, live, using the day's rate in `ExchangeRates`. Switch it back to XAF and every
read is back to native XAF instantly, nothing was lost, because nothing on the sheet ever
moved. Any read action also accepts a one-off `currency` field in its own payload (e.g.
`{ "action": "accounts.list", "payload": { "currency": "EUR" } }`) to preview a different
currency without touching the persisted `DisplayCurrency` setting at all.

A transaction's currency is always its account's currency, there's no per-transaction
Currency column, an account is where a currency lives. Known limitation: a Transfer
between two accounts held in different currencies is read back in the *From* account's
currency, the amount that actually landed in the To account isn't separately reconciled,
this only matters once you actually have accounts in more than one native currency.

## No Users tab

There isn't one. All user data — identity via Firebase Authentication, the PIN hash and
the household-access-revoked flag via Firestore — lives solely in Firebase (see
`PRD-AUTH-FIREBASE.md`). This Sheet is the ledger only: accounts, categories,
transactions, transfers, budgets, currency rates. It has never held a password and no
longer holds a PIN hash either. Apps Script has no `auth.*` actions and no crypto of any
kind in it.

## Lists

Dropdown source values for every select column above. Add a row here to make a new value
selectable elsewhere, e.g. a new account Type or a new Frequency.

## How inserts work

`Transactions` and `Transfers` are pre-filled with their formula columns down to rows
5,000 and 2,000. Apps Script never uses `appendRow()` (which would land past that
pre-filled range), it finds the first row whose ID column is still blank and writes only
the plain-value columns there, leaving that row's pre-existing formulas untouched. Don't
insert rows above the last used row by hand for the same reason, it shifts everything out
of alignment with the formulas already sitting below.
